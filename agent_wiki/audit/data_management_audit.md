## 2. Disconnected & Dropped Simulation Parameters

An audit of the data payload generated by `DataManagementWidget._process_manual_data()` compared against downstream consumers (`DataIntegrationEngine`, `SurrogateEngineWrapper`, `FastProfileGenerator`) revealed several user inputs that never influence simulation or optimization:

### 2.1 Critical Viscosity Typo in Detailed PVT
- **Location**: `ui/data_management_widget.py` lines 1027 & 1042
- **Issue**: Lookups use `'co2_visc'` and `'oil_visc'`:
  ```python
  co2_viscosity = np.array([self.manual_inputs_values.get('co2_visc', 0.02)] * len(pressure_points))
  oil_viscosity_cp = self.manual_inputs_values.get('oil_visc', 0.8)
  ```
  However, in `MANUAL_PVT_DEFS`, the defined keys are `'oil_viscosity_cp'` and `'gas_viscosity_cp'`.
- **Impact**: In detailed PVT mode, user-entered oil and CO₂ gas viscosities are **ignored**; the engine silently falls back to 0.8 cP and 0.02 cP.
- **Remediation**: Correct lookup keys to `'oil_viscosity_cp'` and `'gas_viscosity_cp'`.

### 2.2 Corey Relative Permeability Inputs Dropped from Payload
- **Location**: `ui/data_management_widget.py` lines 1323–1333 (`integration_data["eor_parameters"]`)
- **Issue**: The UI collects `s_gc` (Critical Gas Saturation), `s_wc` (Connate Water Saturation), `s_orw` (Residual Oil Saturation to Water), `n_w` (Water Corey Exponent), and `n_ow` (Oil-in-Water Corey Exponent). However, `_process_manual_data()` omits them when populating `integration_data["eor_parameters"]`.
- **Impact**: `DataIntegrationEngine._create_eor_parameters()` supports all of them, but because `DataManagementWidget` drops them, the simulation engine runs with hardcoded defaults (`s_gc = 0.05`, `s_wc = 0.20`, `s_orw = 0.20`, `n_w = 2.0`, `n_ow = 2.0`).
- **Remediation**: Pass all Corey rel-perm parameters from `self.manual_inputs_values` into `eor_parameters`.

### 2.3 Phantom Geological Categoricals
- **Location**: `ui/data_management_widget.py` lines 91–102
- **Issue**: `rock_type`, `depositional_environment`, and `structural_complexity` are defined in `MANUAL_RES_DEFS` as combobox configurations, but are **never instantiated or added to any UI layout** in `_create_reservoir_tab()`.
- **Impact**: Values remain permanently `None`.
- **Remediation**: Either render a dedicated "Geological Environment" QGroupBox on the Reservoir tab or remove these definitions if surrogate simulation does not consume facies models.

### 2.4 Unused Reference Pressure (`ref_pres`)
- **Location**: `ui/data_management_widget.py` line 110
- **Issue**: Exposed on the PVT UI, but never mapped to `PVTProperties`, `ReservoirData`, or the engine.
- **Impact**: Dead user input.
- **Remediation**: Connect to datum pressure initialization or remove from the interface.

### 2.5 Wellbore Radius & Skin Factor Disconnected from Deliverability
- **Location**: `ui/widgets/manual_well_dialog.py` lines 77–78, 380–382
- **Issue**: `WellboreRadius` ($r_w$) and `SkinFactor` ($s$) are saved into `WellData.properties`, but `surrogate_engine.py` and `FastProfileGenerator` evaluate well deliverability using a flat `productivity_index = 5.0` STB/d/psi.
- **Impact**: Skin damage and well completion diameter have zero effect on well drawdown or reservoir voidage.
- **Remediation**: Augment well deliverability calculations in `surrogate_engine.py` using composite Darcy inflow:
  $$J = \frac{2\pi k h}{\mu \left(\ln\frac{r_e}{r_w} + s\right)}$$

### 2.6 Detailed Water PVT (`PVTW`) Dropped
- **Location**: `ui/widgets/pvt_editor_dialog.py` & `ui/data_management_widget.py` line 1015
- **Issue**: The user can input water FVF and compressibility in `PVTEditorDialog`, but `_create_pvt_properties_from_ui()` only reads `PVTO` and `PVTG`.
- **Remediation**: Extract `PVTW` values into `PVTProperties.water_fvf` and `PVTProperties.water_compressibility`.

### 2.7 EOS Flash Plotting Ignores Custom Components in Dialog
- **Location**: `ui/widgets/pvt_editor_dialog.py` lines 584–608
- **Issue**: In `_run_and_plot_full_pvt_range()`, `eos_params` is extracted from UI, but `SolventExtendedPVTEngine` is initialized with hardcoded `x_co2 = 0.15` and default internal tables. The custom components, mole fractions, and $k_{ij}$ matrix from the table are ignored.
- **Remediation**: Feed the custom `eos_params` into the thermodynamic flash engine.

## 3. Dead Code & Crash Hazards

### 3.1 Dead Methods Calling Non-Existent `self.pvt_table`
- **Location**: `ui/data_management_widget.py` lines 1066–1119
- **Methods**: `_add_pvt_row(self)`, `_remove_pvt_row(self)`, `_plot_pvt_data(self)`
- **Defect**: These methods operate on `self.pvt_table`, which was removed when `PVTEditorDialog` was introduced. Calling any of these immediately raises an unhandled `AttributeError`.
- **Remediation**: Delete these legacy methods.

### 3.2 Missing `use_geostatistical_model_checkbox` Attribute
- **Location**: `ui/data_management_widget.py` lines 1668–1674 & line 2052
- **Defect**: In `load_project_data()`:
  ```python
  if self.reservoir_data.geostatistical_params:
      self.use_geostatistical_model_checkbox.setChecked(True)
  ```
  `self.use_geostatistical_model_checkbox` is not instantiated anywhere in `_setup_ui()`. Loading any `.tphd` project containing geostatistical parameters crashes with `AttributeError`.
- **Remediation**: Add `hasattr(self, 'use_geostatistical_model_checkbox')` guard.

### 3.3 Dead Well Creator
- **Location**: `ui/data_management_widget.py` lines 1764–1782 (`_get_or_create_well`)
- **Defect**: Defined, never invoked or referenced anywhere.
- **Remediation**: Delete or document intended use case.

### 3.4 Unpopulated 3D Canvas
- **Location**: `ui/data_management_widget.py` lines 356–357, 1537
- **Defect**: `self.canvas_3d` and `self.ax_3d` are allocated in the "3D View" tab, but no method in `DataManagementWidget` ever plots data to them. It displays a permanently blank Matplotlib box.
- **Remediation**: Either render 3D well trajectories and reservoir boundary boxes or replace with the dedicated `geomechanics_3d_view.py`.

### 3.5 Fallback Import Class Name Mismatch
- **Location**: `ui/data_management_widget.py` lines 34 & 44
- **Defect**: Line 34 attempts `from .widgets.log_viewer_dialog import WellViewerDialog`. The `except ImportError:` fallback on line 44 defines `class LogViewerDialog(QDialog): pass`. If an import error occurs, line 1793 crashes with `NameError: name 'WellViewerDialog' is not defined`.
- **Remediation**: Rename fallback class to `WellViewerDialog`.

### 3.6 Duplicate Widget in Splitter
- **Location**: `ui/widgets/log_viewer_dialog.py` lines 171 and 193
- **Defect**: `splitter.addWidget(self.logs_group)` is called twice, distorting the intended layout.
- **Remediation**: Remove line 193.

## 4. Software Engineering Anti-Patterns

### 4.1 Keyword Mismatch Disabling Min/Max Validation
- **Location**: `DataManagementWidget.SURROGATE_TUNING_DEFS` vs `ParameterInputGroup.__init__()`
- **Defect**: `SURROGATE_TUNING_DEFS` declares bounds using `'min'` and `'max'`. `ParameterInputGroup` looks for `'min_val'` and `'max_val'`. As a result, bounds validation never runs for any surrogate tuning parameter.
- **Remediation**: Change `ParameterInputGroup` to accept `kwargs.get("min_val", kwargs.get("min"))`.

### 4.2 Disabling Coordinates on Perforated Wells
- **Location**: `ui/widgets/manual_well_dialog.py` lines 302–305
- **Defect**: `self.key_param_widgets["SurfaceX"].setEnabled(not has_perforations)` disables surface coordinate editing when perforations exist.
- **Remediation**: Remove this disabling logic; surface coordinates and downhole perforations are independent.

### 4.3 3D Coordinate Flattening
- **Location**: `ui/widgets/manual_well_dialog.py` lines 339–340
- **Defect**: Converting 2D path points to 3D forcibly replaces the $Y$ coordinate with $0.0$, discarding `SurfaceY`.
- **Remediation**: Use `[p.x(), sy, p.y()]` when constructing 3D path arrays.

### 4.4 Mutable Default Argument
- **Location**: `ui/widgets/manual_well_dialog.py` line 88: `def __init__(self, existing_names: List[str] = [], ...)`
- **Remediation**: Use `existing_names: Optional[List[str]] = None`.
